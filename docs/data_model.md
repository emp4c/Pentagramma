# Data Model

All core data structures used across the system.
These are defined in `src/models.py` and imported by all components.
No component defines its own data structures — everything lives here.

---

## OHLCVBar

Represents one 1-minute bar.

```python
@dataclass(frozen=True)
class OHLCVBar:
    ticker:    str
    timestamp: datetime          # UTC, bar close time
    open:      float
    high:      float
    low:       float
    close:     float
    volume:    float
```

**DB schema** (long-term OHLCV DB, SQLite table `bars`):

| Column | Type | Constraints |
|---|---|---|
| ticker | TEXT | NOT NULL |
| timestamp | TEXT (ISO8601 UTC) | NOT NULL |
| open | REAL | NOT NULL |
| high | REAL | NOT NULL |
| low | REAL | NOT NULL |
| close | REAL | NOT NULL |
| volume | REAL | NOT NULL |

Primary key: `(ticker, timestamp)`

## MachineStatus

The runtime state of the trading machine. One instance per session.

```python
@dataclass
class MachineStatus:
    position:          Literal["IDLE", "LONG"]
    active_stop_price: float | None      # current stop-loss price; None when IDLE or unknown
    initial_nav:       float             # NAV at session start (cash + value of shares)
    session_date:      date              # calendar date of the current session (EST)
    pending_orders:    Dict[str, Literal["BUY", "SELL"]]  # order_id → side; {} when no open orders
    bar_count:         int               # total bars processed this session (for pivot timing)
```

## AnalystOrder

An instruction from the analyst to the trader. The trader translates these into `BrokerOrder` objects.

```python
@dataclass
class AnalystOrder:
    type: Literal[
        "CANCEL_ALL_BUYS",
        "BUY_LIMIT",
        "SELL_STOP",       # stop-loss sell; triggers when price drops to or below limit
        "SELL_MARKET",
        "UPDATE_STOPLOSS",
    ]
    price:        float | None = None    # limit price (BUY_LIMIT, SELL_STOP, UPDATE_STOPLOSS)
    size:         Literal["FULL_AVAILABLE_CASH", "ALL_SHARES"] | None = None
    condition:    str | None = None      # e.g. "on_fill:<order_id>"
```

---

## BrokerOrder

A structured order ready to be sent to the broker bus.

```python
@dataclass
class BrokerOrder:
    order_id:     str                    # UUID generated by the trader
    ticker:       str
    side:         Literal["BUY", "SELL"]
    order_type:   Literal["LIMIT", "MARKET", "STOP_LIMIT", "CANCEL"]
    limit_price:  float | None           # None for MARKET orders
    quantity:     float                  # number of shares (computed by trader from cash)
    condition:    str | None             # conditional execution instruction
    created_at:   datetime
```

---

## ExecutionConfirmation

Returned by the broker bus (live or test) when an order is filled.

```python
@dataclass(frozen=True)
class ExecutionConfirmation:
    confirmation_id: str                 # broker-assigned, used for deduplication
    order_id:        str                 # matches BrokerOrder.order_id
    ticker:          str
    side:            Literal["BUY", "SELL"]
    filled_quantity: float
    filled_price:    float
    filled_at:       datetime            # UTC
```

---

## LedgerEntry

One record per execution confirmation. The bookkeeper appends one per confirmation.

```python
@dataclass(frozen=True)
class LedgerEntry:
    entry_id:        str                 # UUID
    confirmation_id: str                 # from ExecutionConfirmation (for traceability)
    ticker:          str
    side:            Literal["BUY", "SELL"]
    quantity:        float
    price:           float
    gross_value:     float               # quantity * price
    fee:             float               # broker fee (0.0 if unknown/test)
    net_value:       float               # gross_value + fee (sign convention: cost is positive)
    cash_after:      float               # bookkeeper cash balance after this entry
    shares_after:    float               # bookkeeper shares held after this entry
    timestamp:       datetime            # UTC
    note:            str                 # free text, e.g. "stop-loss triggered"
```

**DB schema** (ledger DB, SQLite table `ledger`):
All fields above as columns. Primary key: `entry_id`.

## Pivot Cache (batch mode only)

Stored as a dict keyed by bar index checkpoint, serialised to `data/pivots_cache/<ticker>_<start>_<end>.json`.

```json
{
  "ticker": "AAPL",
  "generated_at": "2026-01-15T10:00:00Z",
  "interval_bars": 30,
  "checkpoints": {
    "0":  [182.10, 184.50, 186.00, ...],
    "30": [183.00, 185.20, 187.10, ...],
    ...
  }
}
```

---

## Notes

- All timestamps are stored and passed as UTC `datetime` objects. Conversion to EST happens only in the analyst (for stop-time checks) and in the report writer (for display).
- `quantity` in orders is always in shares (fractional shares permitted as float).
- The bookkeeper is the single source of truth for `cash` and `shares_held`. The broker API reconciliation updates these values in place; the ledger is never modified retroactively.
